# ChopDot Friend Pilot Run Packet

Status: `ready-to-run`
Date: 2026-06-21
Programme: Track 1 usability + Programme B boundary comprehension

## Purpose

This is the short run sheet for a real friend pilot. Use it alongside
`friend-pilot-script-2026-06-20.md`.

The goal is not to teach people ChopDot. The goal is to see whether people can
open the product, understand their own next action, avoid unsafe money
assumptions, and explain the final record without technical coaching.

## Local Setup

Start the app:

```bash
npm run dev
```

Use one local session name per pilot:

```text
friend-pilot-YYYY-MM-DD
```

To generate a ready-to-run session packet with all links and ledger templates:

```bash
npm run pilot:friend-session -- --session friend-pilot-YYYY-MM-DD --base-url http://127.0.0.1:5173
```

The generated file lands under:

```text
artifacts/friend-pilot/friend-pilot-YYYY-MM-DD/run-sheet.md
```

Use separate devices or separate browser profiles. Do not role-switch on one shared screen
for real pilot evidence.

## Five Questions Before Any Click

Ask every participant:

1. What is this group trying to finish?
2. What is your next step?
3. Who is the group waiting on?
4. What would be unsafe to assume from this screen?
5. What record would you trust later?

Do not coach the answer before the participant speaks.

## Required Evidence

For every scenario, capture:

- participant pseudonyms only;
- device or browser profile used;
- route used;
- first interpretation before coaching;
- coaching needed: `none`, `minor`, or `blocking`;
- action completed;
- blocker explanation;
- unsafe assumption check;
- money-model check: participant explains what was claimed, confirmed,
  approved, released, and closed in plain language;
- screenshot after action;
- receipt/return check: participant can explain the trusted record, or where they
  would return if the scenario does not close;
- receipt screenshot if closeout is reached;
- pass/fail decision;
- required product fix before promotion.

## Unsafe Assumptions That Fail The Scenario

Fail the scenario if a participant believes:

- ChopDot holds or protects the money;
- `Mark paid` means receiver confirmation;
- approval means payment happened;
- token or webhook evidence confirms receipt;
- release record means the recipient received money;
- closeout means every open item was paid;
- emergency details are public by default;
- live `.dot` or host-native proof is complete today.

## Recording Results

Record real outcomes in:

```text
docs/chopdot-dot/friend-pilot-results-ledger-2026-06-20.md
```

Do not change a scenario to `pass` unless every evidence field is complete. The
scorecard must stay below 9/10 until the ledger records real participant
evidence. A pass requires `Coaching needed: none`; if the participant needs
minor or blocking coaching, record the scenario as `fail` or `blocked` and name
the product fix.

## Fast Verification Before Running

Run:

```bash
npm run pilot:friend-session -- --session friend-pilot-YYYY-MM-DD --base-url http://127.0.0.1:5173
npm run validate:friend-pilot
npm run validate:use-case-9
```

Expected result:

```text
friend-pilot script OK
friend-pilot run packet OK
friend-pilot results ledger OK
use-case 9/10 scorecard OK
```

Generating a packet does not promote any scenario. Only completed rows in
`friend-pilot-results-ledger-2026-06-20.md` can promote a use case toward 9/10.
