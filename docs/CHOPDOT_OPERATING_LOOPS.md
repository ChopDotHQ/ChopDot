# ChopDot Operating Loops

Purpose: keep ChopDot execution anchored to product proof, task queues, and reviewable evidence instead of chat memory.

## Active Loop Shape

- Start from the product cockpit or `.knowns/tasks` when the work is product or operator focused.
- Keep the current product spine explicit: `Catch -> Management -> Payout -> History`.
- Use screenshot/user-flow evidence for user-facing changes before claiming the flow is ready.
- Keep protocol, wallet, proof, native, and settlement claims separate from normal user copy unless the implementation evidence is current.

## AgentOps Boundary

- AutoBots owns shared governance and cross-repo hydration.
- ChopDot owns local product truth, cockpit state, and user-facing readiness evidence.
- Reusable lessons move through `docs/AGENT_DOCTRINE_FEEDBACK.md` before any shared-doctrine promotion.
