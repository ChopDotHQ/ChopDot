# ChopDot Agent Doctrine Feedback

Purpose: capture reusable lessons from ChopDot without flattening closeout-specific product truth into the shared `AutoBots` baseline.

## Keep local

- closeout-driven settlement thesis
- wallet-model and Polkadot-specific product language
- `.knowns/tasks` execution surface and local-only asset handling
- current release and contract-specific rollout constraints

## Candidate reusable lessons

- preserve human edits in durable task queues instead of regenerating them blindly
- keep active execution queues separate from long-horizon strategy documents
- require a compact repo-first read order before asking a model to plan or summarize
- route non-trivial product work through explicit role loops with verifier and stop condition instead of letting one blended agent voice own product, UX, engineering, research, and proof at once

## Rejected for baseline

- product messaging unique to ChopDot
- chain- or contract-specific release assumptions
