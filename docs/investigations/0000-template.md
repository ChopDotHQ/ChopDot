## Question

State one bounded uncertainty to resolve.

## Decision at risk

What product, authority, money, security, privacy, migration, accessibility,
agent-system, provider, or release decision could change? Name affected
requirement, invariant, product-card, and ADR IDs.

## Declared universe and exclusions

Define the repositories, branches, files, primary sources, versions, networks,
accounts, devices, participants, time window, experiments, and cases in scope.
List explicit exclusions. Do not claim complete coverage without a closed and
measured universe.

|---|---|---|---|---|
| | | | | |

`source-only`, `unit`, `simulated-integration`, `simulated-host`,
`exact-candidate`, `real-host-chain`, `live-user`, `release`, and
`local-blocked`.

## Method

Describe source review, reproduction, experiment, threat model, comparison,
user walkthrough, environmental readback, and evaluation. Name commands, CWD,
candidate identity, exact counts, evaluator identity, and privacy/redaction
boundary. Separate simulated work from real environments and real participants.

## Facts

List only directly observed, cited facts. Each material fact must point to a
source or experiment row.

## Inferences

State reasoned conclusions and the facts supporting them. Do not restate an
inference as an observation.

## Assumptions and unknowns

List unverified premises, inaccessible evidence, stale/cross-root context,
coverage limits, and conditions that could change the conclusion.

## Counterevidence and adversarial checks

Record the strongest counterexample, failure path, disconfirming source, wrong
actor/root/network/candidate case, interruption point, or alternate explanation
attempted. Include the result and remaining gap.

## Authority and effect impact

Who could gain or lose the ability to read, create, change, confirm, recover,
publish, or approve state? List any proposed external effect, credential,
approval, idempotency key, readback, and reconciliation requirement. An
investigation cannot itself grant authority.

## Product and build impact

Which product card, invariant, ADR, interface, source path, test, evaluator,
release threshold, provider adapter, or user journey changes? What must remain
unchanged?

## Decision

`ACCEPT` | `ACCEPT WITH CONDITIONS` | `HOLD` | `REJECT / REDESIGN`

Explain why the recorded evidence permits this decision and no stronger one.

## Required follow-up evidence

Name the smallest exact proof needed next, responsible owner, target evidence
level, retry/iteration limit, approval boundary, and stop condition.

## Documentation and provenance updates

List sources that must change, generated views to regenerate, historical files
to preserve, and exact links/digests to add to the accepted outcome packet.
