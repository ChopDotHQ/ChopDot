# ChopDot Product Roadmap

The roadmap is organized around user outcomes, not technical lanes.

Routing rule:

- `product/story-map.md` owns the user-journey sequence.
- `product/cards.md` owns buildable execution slices.
- The cockpit is a generated workbench for status and evidence, not the source of product truth.
- If the cockpit next card does not fit the active story-map sequence, reframe or park the card before implementation.

## Now

Outcome: first useful shared state in under 30 seconds.

Primary cards:

- `P-001` Dinner split pay-moment capture
- `P-002` No-app friend payment link
- `P-003` Confirm received
- `P-004` Close with readable saved record
- `P-011` Product language cleanup
- `P-012` Receipt capture without manual-first entry
- `P-014` Product cockpit upgrade

Done means a first-time user can understand the immediate job, act, and see what changed without reading a technical explanation.

## Next

Outcome: repeated group-money modes feel like native ChopDot, not lab surfaces.

Primary cards:

- `P-005` Spend Card capture path
- `P-006` Savings circle round
- `P-007` Emergency pot privacy flow
- `P-008` Community fund role flow
- `P-009` Agent wallet journey testing
- `P-015` Friend-pilot readiness scorecard

Done means each mode has one primary job, one next action, role-aware views, and screenshot-backed agent observations.

## Parallel

Outcome: Polkadot-native work stays honest, useful, and invisible to normal users.

Primary cards:

- `P-010` Polkadot-native session boundary
- `P-013` Competitor and 10x benchmark

Done means live/native gaps are explicit and local product progress is not blocked by external `.dot` availability.

## Continuous

Outcome: the product flywheel keeps context, decisions, and evidence current.

Primary cards:

- `P-014` Product cockpit upgrade
- `P-016` Product resume for future agents

Done means every meaningful product change updates cards, evidence, decisions, or history.
