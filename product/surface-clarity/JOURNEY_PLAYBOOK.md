# Journey prompts and retained meaning

These are reviewer prompts, not new product rules, certified task paths or
claims that every listed branch exists. Resolve states and consequences against
each journey's approved sources and documented integration impacts. Record an
unsupported capability as a limitation; do not implement it to satisfy a prompt.

| Journey | Question to ask before the action | Continuity / recovery to inspect |
|---|---|---|
| J01 Enter | Are you entering an account, continuing locally or joining a group? | Invite context; guest/account boundary; interrupted entry |
| J02 Home | What needs your attention, and where would you go first? | Empty versus returning state; refreshed accepted records; unavailable routes |
| J03 Create group | Who and which currency will this group use? | Cancel/reopen; saved group; correct next destination |
| J04 Invite / join | Which group are you joining, and as whom? | Pending/expired/unavailable invite; duplicate join; existing identity |
| J05 Add expense | Who paid, who is included, and how is this exact amount divided? | Draft Back/reopen/reload; validation; save once; affected group return |
| J06 Inspect / correct | What changed from the earlier expense, and what will your correction affect? | Accepted lineage/history; cancel; review reset; permission refusal |
| J07 Review / agree / issue | Are you agreeing, raising an issue or responding as its owner? | Other participant's view; issue ownership and cancellation; reset after edit |
| J08 Group Home | What changed, who owes what, and what can you act on? | Actual underlying accepted state; actor changes; offline/waiting/empty |
| J09 People | Is this a local name, linked participant or payment destination? | Membership/role boundaries; selected person/group context |
| J10 Position | Which person, groups, items and currency explain this number? | Inspect sources; excluded unresolved items; scope retained into settlement |
| J11 Settle | Are you settling a group, a person or selected items; what remains afterward? | Equivalent approved scopes; guards; partial amounts; cancellation |
| J12 Complete settlement | Is this confirmed, pending, unknown or failed, and what is safe to do now? | Same operation identity; no invented finality; owner recovery; recipient view |
| J13 Request | Who receives the request, for which amount and sources? | Review before send; pending state; requester/recipient boundaries |
| J14 Receive | Are you sharing a destination or recording a received payment? | Missing details; visibility; no destination-to-payment equivalence |
| J15 History | Is this payment final, and which facts establish that? | Empty history; unresolved result; receipt/proof access; correct signs |
| J16 Savings group | What is the goal, date, currency and participation? | Early field validation; draft retention; truthful holding state |
| J17 Contribute / withdraw | Is this a proposal, permission to proceed or confirmed movement? | Review amount/destination; pending/failed/unknown fixture; accepted history |
| J18 Activity | What actually changed, and what requires your action? | Notification versus fact; actor-filtered action; relevant owning destination |
| J19 Insights | What records, dates and currency support this insight? | Empty/insufficient data; recognition rather than raw engineering prose |
| J20 Payment methods | Whose method are you changing, and where will it be used or visible? | Missing/incomplete data; cancel; return to original task |
| J21 Wallet | What is connected or simulated, and would this action sign anything? | Disconnected/unavailable/denied; correct return; no simulated signing claim |
| J22 QR | What kind of reference was scanned, and what will opening it do? | Before first scan versus rescan; unknown/malformed/unsupported reference |
| J23 Import | What will be added, rejected or reviewed before acceptance? | Preview/errors; identity and lineage boundaries; duplicates and interruption |
| J24 Export | Which scope is included, and what does this export actually prove? | Preparation versus completion; cancellation; exact details reachable |
| J25 Storage / recovery | What is stored here, what is recoverable, and what remains unavailable? | Browser-local limits; interrupted restore; conflict and authority boundaries |
| J26 Lifecycle | Are you leaving, archiving or finishing; what obligations and history remain? | Permissions; unresolved items; future access; accidental confirmation |
| J27 Account | Which identity/preferences are affected, and can you safely leave this task? | Guest/account boundary; denied capability; Back; retained local data limits |
| J28 Recovery | What is known, what is uncertain, and which owning task can resolve it? | Same operation/reference; safe retry; no cross-owner mutation or invented success |

## Cross-journey sequences

Review at least the sequences touched by a change; do not stop at screenshots:

- Create → invite/join → group → add → inspect/correct → review/issue → group.
- Position/group/person → scoped settlement → result → history or recovery → owner.
- Savings group → contribution/withdrawal → progress/result → refreshed group.
- Activity/notification → owning task → completion → updated attention state.
- Payment details/wallet/QR → initiating task, preserving its original context.
- Import/export/storage/lifecycle/account → result or recovery, with a valid exit.

Use the canonical local prototype record. Participant switching and external
preconditions use explicit synthetic test controls; run orientation and normal
navigation without those controls. Record which fixtures were used, separately
from ordinary user behavior. Never use real funds, signatures or personal data.

## Neutral comprehension probes

Give a task, not a navigation tutorial: “You paid for dinner. Record it for these
people,” or “You want to pay only this group's part and leave the other group
open.” Before the consequential control ask, “What do you expect will happen?”
Then ask, “What is still unresolved?” Watch where they hesitate, misinterpret a
label, lose scope or need help. Check their answer against approved meaning.

Do not tell them the desired answer, call agent walkthroughs human testing, or
combine distinct actor/state results into one satisfaction score. Capture task
completion, consequential misunderstandings, recoverability and assistance;
use elapsed time only with comparable tasks and contexts. Set acceptable results
for the bounded change before inspecting observations. A financially consequential
misunderstanding requires investigation even if average task time improves.
