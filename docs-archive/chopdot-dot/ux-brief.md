# ChopDot.dot UX Brief

## Visual Thesis

Calm financial operations: clear state, precise actions, restrained surfaces, and one active chapter as the visual anchor.

## Content Plan

The app should be understood from headlines alone:

1. Choose the real-world job.
2. See current state.
3. Act on the next blocker.
4. Close with a receipt.

## First Screen

Use real-world choices, not technical modes:

- Run a savings circle
- Coordinate emergency help
- Manage a community fund
- Split shared expenses
- Collect event deposits

Each choice should show one sentence:

- who it is for
- what it tracks
- what closeout means

## Status-First Layout

Every mode should show:

- current state
- next actor
- blockers
- money movement claims
- confirmations
- closeout readiness

The status board comes before history tables or technical details.

## Copy Rules

Use:

- `claimed`
- `confirmed`
- `approved`
- `needs review`
- `released outside ChopDot`
- `closed with open items`
- `receipt`

Avoid:

- escrow
- protected funds
- guaranteed payout
- verified payment
- smart contract
- immutable settlement
- DAO vote
- yield

## Interaction Thesis

- Keep each screen to one primary action.
- Show blockers as named actor/action pairs.
- Treat closeout as a deliberate review moment, not a background success toast.
- Export should ask whether the user wants full or redacted receipt.

## Design Guardrails

- Mobile-first, desktop-clean.
- Cards only for repeated objects or framed tools.
- No blockchain onboarding before the chapter job is clear.
- No public proof or wallet status as the first visual object.
- Financial and privacy-sensitive states must use conservative labels and visible confirmations.
